# 修复 sret 指针寄存器映射：应使用 X8 而非 X0

## 问题

返回 >16 字节结构体的函数（sret 调用约定）在重编译 lifted IR 后 segfault。lifter 将 sret 指针映射到 X0（按参数顺序分配的第一个寄存器），但 AAPCS64 规范规定间接结果位置寄存器是 **X8**。

导致的错误：

1. **被调用方**：从 X0 读取 sret 指针（X0 实际存的是第一个整型参数，如 `a=1`），然后向地址 `0x1` 写入 → segfault。
2. **调用方（marshallArgs）**：从 X0 读取 sret 实参（得到 `a=1`），将 `inttoptr 1 to ptr` 作为 sret 缓冲区传递 → 被调用方向地址 0x1 写入 → segfault。

对于 `scale_triple`（既有 sret 又有 large struct 参数），偏移级联放大：`sret ← X0（实为 Triple*），Triple* ← X1（实为 factor=5），factor ← X2（垃圾值）`。被调用方先通过 Triple 指针写入（合法栈地址，静默破坏内存），随后在 sret 写入时 segfault。

## 根因

`backend_tv/arm2llvm.cpp` 中有两处将函数参数按顺序映射到 X0、X1、X2…，均未检查 `sret` 属性：

- **被调用方入口绑定**（约 3384 行）：`liftedFn` 的参数按顺序存入 `RegFile[AArch64::X0 + scalarArgNum]`。
- **调用方 marshallArgs**（约 1047 行）：参数按顺序从 `AArch64::X0 + scalarArgNum` 读取。

两者都没有检查 `arg->hasStructRetAttr()` 来把 sret 参数重定向到 X8。

## 修复

`backend_tv/arm2llvm.cpp` 和 `backend_tv/arm2llvm.h`，共三处改动：

### 1. marshallArgs 签名 — 增加 callee Function* 参数

```cpp
// 改前：只有 FunctionType，无法访问参数属性
vector<Value *> marshallArgs(FunctionType *fTy);
// 改后：可以检查 callee 的参数是否有 sret 属性
vector<Value *> marshallArgs(FunctionType *fTy, Function *callee = nullptr);
```

### 2. marshallArgs 体 — 从 X8 读取 sret

在参数类型分派之前，为第一个参数的 sret 做特殊处理：

```cpp
if (isFirstArg && hasSRet) {
    param = readFromRegTyped(AArch64::X8, getIntTy(64));
    param = new IntToPtrInst(param, PointerType::get(Ctx, 0), "", LLVMBB);
    args.push_back(param);
    continue;  // 不递增 scalarArgNum
}
```

### 3. 被调用方入口绑定 — sret 存入 X8

在 aggregate/scalar 分派之前，检查 `hasStructRetAttr()`：

```cpp
if (arg->hasStructRetAttr()) {
    createStore(&*arg, RegFile[AArch64::X8]);
    goto end;  // 不递增 scalarArgNum
}
```

### 4. 调用点更新

```cpp
// 改前：
auto args = marshallArgs(FC.getFunctionType());
// 改后：
auto args = marshallArgs(FC.getFunctionType(),
                          dyn_cast_or_null<Function>(FC.getCallee()));
```

## 影响

- `make_triple(long, long, long)` — 24 字节结构体返回，sret 走 X8 → 正常。
- `scale_triple(Triple, long)` — sret (X8) + large struct 参数 (X0) + 标量 (X1) → 映射正确。
- 小结构体返回（≤16 字节，由 X0 直接返回值）不受影响，它们不使用 sret。
